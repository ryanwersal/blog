I started using [Claude Code](https://www.anthropic.com/claude-code) a bit over a week ago and it's changing how I think about AI coding assistants. It's rather remarkable how advanced my experience has become in just a number of weeks. I had tried out the latest and greatest [Github Copilot](https://github.com/features/copilot) features with the most powerful and recent models and it...fell flat. I had to be incredibly prescriptive about what to change and where and, more often than not, _how_. It really didn't give me any wins productivity-wise.

Then I used [Cursor](https://www.cursor.com) which, [as seen previously on this blog](/posts/prompt-engineering-speaking-ai-language), was a dramatic improvement! This blog was the first proper ["Vibe Coding"](https://simonwillison.net/2025/Mar/19/vibe-coding) experience I had. It truly made Copilot feel like a toy.

But now I'm left with the prospect that I'm quite possibly _more productive_ leveraging Claude Code as my "daily driver" instead of an actual code editor! I've been experimenting with `tmux` to multiplex several Claudes together and will likely post about that more in the coming weeks as the setup evolves.
